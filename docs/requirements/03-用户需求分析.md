# 用户需求分析报告

> 调研时间：2026-05-16

---

## 一、目标用户画像

| 用户群体 | 占比 | 典型场景 | 核心诉求 |
|---------|------|---------|---------|
| 开发者/工程师 | ~35% | 项目文档、README 转 PDF、技术报告 | 代码块高亮、技术排版、离线处理 |
| 学生/研究人员 | ~25% | 论文草稿、作业提交、笔记导出 | 数学公式、目录生成、页码 |
| 求职者 | ~15% | 简历/Resume 导出 | 模板美化、精确排版、PDF 一致性 |
| 技术写作者 | ~15% | 用户手册、API 文档、教程 | 表格渲染、批量导出、专业排版 |
| 其他（律师、商务等） | ~10% | 合同、报告、备忘录 | 表格精确、页眉页脚、水印 |

## 二、用户痛点（按严重程度排序）

### P0 - 致命痛点（不解决用户直接流失）

#### 1. 预览与 PDF 输出不一致
- 预览效果与导出 PDF 差异大（字体、行距、间距全变）
- **根因**：依赖浏览器 `window.print()`，CSS `@media print` 规则导致样式丢失
- **影响**：几乎所有用户

#### 2. 代码块样式丢失
- 语法高亮在 PDF 中消失
- 长代码行溢出页面边界
- 代码块背景色不显示
- 代码跨页断行位置不合理
- **影响**：核心用户（开发者）的第一需求

#### 3. 图片处理问题
- 本地图片路径无法解析
- 网络图片离线时无法加载
- 图片尺寸失控（过大或过小）
- 图片跨页被截断
- **影响**：约 60% 的用户

### P1 - 严重痛点（强烈期望改进）

#### 4. 中文/CJK 字体支持差
- 中文字符显示为方框、乱码或默认字体不美观
- GitHub Issues 中相关 issue 数量排名前三
- **影响**：中国市场巨大

#### 5. 表格渲染质量差
- 复杂表格对齐错乱
- 超宽表格溢出页面
- 表格跨页表头不重复
- **影响**：技术写作者、开发者

#### 6. 页面控制缺失
- 无法控制分页位置
- 标题被孤悬在页面底部
- 无法设置页面边距
- 无法选择纸张大小
- **影响**：几乎所有有排版需求的用户

#### 7. 数学公式不支持
- LaTeX 公式（$...$ 和 $$...$$）显示为原始文本
- **影响**：学术用户（刚需）

### P2 - 一般痛点（体验提升）

| 痛点 | 影响 |
|------|------|
| 目录（TOC）无法生成 | 长文档用户 |
| 页眉页脚不可控 | 正式文档用户 |
| 导出 PDF 文件过大 | 分享/上传场景 |
| 无主题/模板选择 | 所有用户 |
| 无自定义 CSS 入口 | 高级用户 |
| 无分页符控制 | 精确排版需求 |

## 三、隐私需求分析

| 关注级别 | 需求 |
|---------|------|
| **极高** | 数据不上传服务器（简历、合同等敏感文档） |
| **极高** | 完全离线可用 |
| **高** | 无追踪/分析代码 |
| **高** | 无第三方资源加载（不泄露内容信息） |
| **中** | 清晰的隐私政策声明 |
| **低** | 本地存储加密 |

**核心定位**：隐私是 Printdown 的核心卖点，必须坚持"完全离线、零上传"。

## 四、功能需求优先级矩阵

### Must-Have（V1.0 必须实现）

| ID | 功能 | 理由 | 难度 |
|----|------|------|------|
| M1 | 预览与 PDF 输出完全一致 | 当前最大痛点，直接影响可用性 | 中 |
| M2 | 代码块完美渲染（高亮、自动换行、行号、跨页） | 核心用户（开发者）第一需求 | 中 |
| M3 | 图片正确处理（尺寸控制、不截断） | 基础内容元素 | 中 |
| M4 | 中文字体完整支持（CJK 字体嵌入） | 中国市场刚需 | 低-中 |
| M5 | 离线/本地处理（数据不上传） | 隐私核心卖点 | 低 |
| M6 | 表格正确渲染（对齐、自适应、跨页表头） | 技术文档核心元素 | 中 |
| M7 | 页面设置（边距、纸张 A4/Letter/A3、方向） | 基础排版需求 | 低 |
| M8 | 实时双栏编辑预览 | 工具基础交互 | 低 |
| M9 | 拖拽/粘贴上传 .md 文件 | 便捷性 | 低 |
| M10 | 页眉页脚自定义（文本、页码、日期） | 正式文档必需 | 低-中 |

### Nice-to-Have（V1.x 增强体验）

| ID | 功能 | 理由 | 难度 |
|----|------|------|------|
| N1 | 数学公式支持（KaTeX） | 学术用户刚需 | 中 |
| N2 | 预设主题/模板（亮色/暗色/学术/简历等） | 差异化竞争力 | 低-中 |
| N3 | 自定义 CSS 注入 | 高级用户强需求 | 低 |
| N4 | TOC 自动生成 | 长文档用户核心需求 | 中 |
| N5 | 页码（位置、格式可选） | 正式文档标配 | 低 |
| N6 | 分页符控制（CSS page-break / MD 扩展语法） | 精确排版 | 低 |
| N7 | GFM 完整支持（任务列表、脚注、删除线） | GitHub 生态兼容 | 低 |
| N8 | 水印支持（文字、透明度） | 文档保护需求 | 中 |
| N9 | Mermaid/流程图渲染 | 技术文档可视化趋势 | 中-高 |
| N10 | 暗色编辑模式 | 用户习惯 | 低 |

## 五、非功能需求

| 维度 | 要求 |
|------|------|
| **性能** | 首屏加载 < 2s（3G 网络）；编辑无卡顿（10 万字文档） |
| **体积** | 初始包体积 < 1MB（gzip）；Service Worker 缓存后离线可用 |
| **兼容性** | Chrome 90+、Firefox 90+、Safari 15+、Edge 90+ |
| **移动端** | 响应式布局，手机可查看预览（编辑体验可降级） |
| **可访问性** | WCAG 2.1 AA 级别 |
| **安全** | 零网络请求处理用户内容；CSP 合规；无 XSS |
| **SEO** | 基础 SEO（Open Graph、描述） |
| **国际化** | 中英双语 UI（初期），i18n 框架预留 |
